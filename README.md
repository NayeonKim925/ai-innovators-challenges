# REPLAN MVP

> **처음이라면**: [인수인계 요약(HANDOFF.md)](docs/HANDOFF.md) · [데모 가이드(DEMO_GUIDE.md)](docs/DEMO_GUIDE.md)

REPLAN은 승인된 범위 안에서 외부 변화를 자동으로 감시하고, 에이전트가 근거와 계산 도구로 일정의 숨은 영향을 미리 알리고 조사하며, 사람이 확인한 결과만 일정에 반영하는 **설비 도입 프로젝트 팀용 작업공간**입니다.

협력사, 공공기관, 문서 작성자는 이 서비스의 사용자가 아닙니다. 프로젝트 운영팀이 하나의 공용 계정으로 기준 일정과 프로젝트 근거를 관리합니다.

## 현재 구현된 흐름

작업공간은 **개요 → 일정 → 감시 → 변경 → 대응안 → 실행 → 이력** 7개 화면이며, 왼쪽 메뉴와 위쪽 단계 표시가 같은 순서입니다.

| 화면 | 사용자가 하는 일 | 시스템이 하는 일 |
| --- | --- | --- |
| 개요 | 지금 할 일과 기록 요약 확인 | 저장된 기록에서 단계 진행 상태를 계산 |
| 일정 | 기준 일정 Excel 연결(hero 데모 또는 업로드) | 원본 파일을 보존하고 작업·선후행·일정·구매 목록을 기준 버전으로 저장 |
| 감시 | 등록 시 위험 브리핑을 읽고 감시를 시작, 감시 피드와 리스크 대장 확인 | 위험 상위 3~5개 브리핑, 수집된 공지의 자동 분류, 대장 상태와 이력 기록 |
| 변경 | 받은편지함에서 협력사 통보를 등록(또는 메시지·수정 Excel·근거 문서), 해석 확인 | 입력을 변경 카드로 정리하고 중복·정정 통보를 구분, 확인 후 영향 분석 시작 |
| 대응안 | 영향과 대응안 비교, 필요하면 에이전트 조사 시작, 조건 확인 후 승인 | 계산기가 완료일·비용·제약을 계산, 조사 결과는 사람이 확인해야 반영 |
| 실행 | 승인한 안을 새 일정 버전으로 확정하고 Excel 내려받기 | 원본 기준 버전은 남기고 새 버전과 Excel 생성 |
| 이력 | 버전·승인·실행·수집·알림 기록 확인 | 기록을 시간순으로 보관 |

## 변경 신호와 외부 RAG

변경 신호는 “일정을 바꿀 수 있는 새 정보”입니다. 협력사 메시지, 수정된 Excel, 업로드 문서, 등록한 공식 출처의 공지, 공휴일·기상 감시 결과가 모두 여기에 해당합니다. 변경 신호 자체가 일정 변경은 아닙니다.

LIVE 외부 공지와 업로드 문서에는 다음 흐름을 적용합니다.

1. 프로젝트별 증거 저장소에 원문, 출처 URL 또는 문서 ID, 수집 시각, 해시를 보존합니다.
2. 원문을 인용 가능한 passage로 나누고 작업명·작업 ID·위험 태그·감시 키워드로 관련 문단을 검색합니다.
3. 검색된 근거, 작업 후보, 검색 기록을 신호에 연결합니다.
4. 팀이 작업·날짜·적용 조건을 확인한 뒤에만 일정 계산을 시작합니다.
5. 승인 직전에는 원문 해시를 다시 확인합니다.

현재 RAG는 **프로젝트 내부 SQLite lexical RAG**입니다. 임의의 웹을 LLM이 탐색하지 않으며, 팀이 업로드했거나 감시 대상으로 등록한 출처만 읽습니다. 벡터 검색과 등록되지 않은 웹 탐색은 후속 운영 단계입니다.

## 구성 요소와 역할

| 구성 | 언제 | 하는 일 | 하지 않는 일 |
| --- | --- | --- | --- |
| **워커** (수집·변화 감지, AI 아님) | 감시 계획을 활성화한 뒤 출처별 주기마다, 또는 **감시 시작** 때 | 허용된 출처·공휴일·기상을 가져와 원문 해시로 실제 변화만 감시 피드에 등록. 근거 문단 색인과 규칙 후보 탐색. 아래 에이전트 실행도 워커 프로세스에서 돌지만 역할은 각 에이전트 몫 | LLM 호출, 일정 변경 |
| **사전 에이전트: 등록 시 브리핑** | 기준 일정 등록 직후 | 계산기가 속성(원산지·통관·인허가·야외) × 여유·주공정으로 위험 순위를 정하고, 에이전트가 도구 확인 최대 3회로 같은 원인 품목을 더하거나 해당 없는 후보를 뺌. 엑셀에 없는 원인(예: 수출 통제)은 에이전트가 읽은 L2 사례가 있을 때만 연결. 상위 3~5개를 근거 작업·품목, 여유 일수, L2 사례, 선제 행동(무엇을 언제까지)과 함께 표시 | 지연 일수 추정(여유로 취약도만 표시), 순위·숫자 변경 |
| **사전 에이전트: 변화 자동 추리기** | 등록 출처에서 새 공지가 들어왔고 규칙 후보가 1개 이상일 때 1회 | 후보를 관련 있음 / 확인 필요 / 무관으로 나누고 원문 인용을 붙임. 무관은 "N건 제외 · 이유 보기"로 접음. 같은 원인의 대장 위험을 '신호 감지'로 연결 | 조사 자동 시작, 작업 연결(`related_task_ids`) 덮어쓰기, 일정 변경 |
| **사후 에이전트: 협력사 통보 조사** (X2) | 사람이 **에이전트로 숨은 위험 조사**를 누를 때 | 대장을 먼저 읽고 같은 원인이면 연결(협력사 통보는 '발생'), 통보와 같은 원인의 공지를 연결하고 통보에 없던 품목을 찾아 여유·조건부 영향을 계산, 확인 질문과 메일 초안 작성. 외부 공지는 '관련 있음' 작업과 사람이 고른 '확인 필요' 작업만 계산. 도구 순서는 정하지 않고 전제 조건만 막음(여유 확인 전 조건부 계산 금지 등) | 일정 수정, 통보에 없던 품목을 사람이 확인하기 전 대응안 비교, 메일 발송 |
| **리스크 대장** | 세 에이전트가 함께 읽고 씀 | 위험마다 상태(예상됨 → 신호 감지 → 발생 → 대응 중 → 종결), 관련 작업·품목, 근거, 변경 이력. 사람이 조사 결과를 '해당함'으로 확인하면 '대응 중' | 에이전트의 '종결' 기록이나 상태 되돌리기(사람만 가능) |
| **계산기** | 항상 | 날짜, 여유, 작업 의존성, 비용, 예산·제약 | 원문 의미 추측 |
| **사람** | 확인과 승인 | 감시 제안 수락, 적용 여부·작업·날짜 확인, '확인 필요' 작업 선택, 대응안 승인, 대장 상태 변경 | - |

LLM에는 등록된 출처의 근거 문단, 기준 일정·구매 목록, 리스크 대장, 계산 결과만 전달됩니다. 제안에는 원문 인용이 필요하며, 서버가 인용문이 실제 근거에 있는지 확인하고 조사 기록·메일 초안·대응안 설명·브리핑 메모에서 계산기가 내지 않은 숫자·날짜는 지웁니다. 사람이 확인하기 전에는 일정과 비용을 변경할 수 없습니다.

## 에이전트 호출 원칙

LLM을 **부르지 않는** 곳: 워커의 수집·해시 비교·규칙 후보 탐색, 계산기, 브리핑의 규칙 순위, 자동 감지된 신호의 영향 정리, 규칙 후보가 0개인 공지(LLM 없이 무관 처리), 공휴일·기상 신호의 분류. 에이전트가 꺼져 있거나 한도를 넘으면 규칙·계산기 결과만 보여 줍니다.

LLM을 **부르는** 곳:

| 언제 | 호출 | 한도 |
| --- | --- | --- |
| 기준 일정 등록 직후 | 브리핑: 도구 확인 최대 3회 + 사례 검색 1회(LLM 최대 5턴), 같은 실행에서 감시 계획 보강 1회 | 사람 쪽 일일 한도에 실행 1건 |
| 등록 출처의 새 공지(규칙 후보 1개 이상) | 변화 자동 추리 1회 | **별도** 일일 한도 `REPLAN_MAX_AUTO_TRIAGE_PER_DAY`(기본 20). 넘으면 "한도 초과 · 규칙 결과만" 표시 |
| 사람이 통보를 등록(잠정 분석) | 작업·날짜를 찾지 못한 통보·공지만 해석 1회 | `REPLAN_MAX_PAID_RUNS_PER_DAY`(기본 20) |
| 사람이 해석을 확인(정식 분석) | 해석(필요할 때) + 계산된 대응안 설명 에이전트(최대 8턴). 자동 추리 결과가 있는 공지는 다시 해석하지 않음 | 위와 같음 |
| 사람이 조사를 시작 | 조사 에이전트 최대 6턴(자동 추리 결과가 없는 공지는 후보 추리 1회 추가) | 위와 같음 |

한도는 호출이 아니라 실행 단위로 하루마다 셉니다. 실제 호출은 키(`API_KEY`·`LLM_MODEL`·`LLM_BASE_URL`)와 `REPLAN_PAID_CALLS_ENABLED=true`가 모두 있을 때만 일어납니다. **재생 모드**(`REPLAN_LLM_MODE=replay`)는 녹화본(`data/llm_replay/hero_demo.json`)만 쓰고 한도에 세지 않으며, 녹화와 다른 요청은 `replay miss`로 멈춥니다. `record` 모드는 녹화본에 없는 요청만 실제로 호출해 저장합니다.

LLM이 설정되지 않았거나 일시적으로 연결되지 않아도 기준 일정·규칙·계산기는 동작합니다. 화면은 이를 “계산할 수 없음”이 아니라 **에이전트 연결 확인 필요**로 표시하고, 이미 계산된 결과는 유지합니다.

## 대표 데모

### X2 — 등록 때 예상한 위험이 협력사 통보로 발생

1. **일정**에서 hero 데모 기준 일정 연결 → **감시**의 등록 시 위험 브리핑: 1순위 중국산 통관 품목(P-A1·P-B·P-C), P-C 여유 0일(주공정) 경고, 에이전트가 L2 사례 RS-019로 연결한 원인 "중국 희토류 자석 수출 통제"(엑셀에는 원산지·통관·품목명만 있음)
2. **감시 시작 · 데모 수집 시뮬레이션**: 합성 공지 N-X2가 들어오고 자동 추리기가 관련 있음 4 · 확인 필요 15 · 무관 12로 분류, 대장 위험이 '신호 감지'
3. **변경**의 받은편지함에서 `대표 데모` 통보(P-A1 통관 지연) → **변경으로 등록** → **해석 확인 후 영향 분석**: 통보 내용만으로는 영향 없음(완료 2027-12-21)
4. **대응안**의 **에이전트로 숨은 위험 조사**: "등록 시 예상했던 위험이 발생함", 통보에 없던 P-C가 허가를 늦게 받으면 최악 2028-02-11, 서류 제출 기한 2027-02-08, 확인 질문과 메일 초안
5. **P-C도 해당함 · 일정 다시 계산**: 추천 조합 2028-01-25(17일 회복)
6. 조건 확인 → 승인 → **새 일정 버전 확정** → **Excel 다운로드**(마지막 완료일 2028-01-25)

보조 장면 **H04**: 설비 반입 완료일 변경 통보를 받은편지함에서 등록하면, 계산기가 통보 지연과 밀린 기간에 새로 걸린 공휴일을 나눠 계산하고 대응안 조합(2027-12-28, 28일 회복)을 추천합니다.

## 실행

### 데모 재생 모드

```sh
cp .env.example .env
# .env에서 REPLAN_DEMO_TOKEN을 로컬 값으로 변경
scripts/demo.sh                # macOS·Linux
# Windows: scripts\demo.cmd
```

`http://localhost:3000`에서 **데모 보기 → 워크스페이스 열기 → 프로젝트 만들기** 순서로 실행합니다. 데모는 별도 데이터 공간에서 `REPLAN_LLM_MODE=replay`로 동작합니다. 녹화된 응답을 사용하므로 API 키·네트워크·비용 없이 대표 흐름을 재현합니다.

### 실제 LLM 모드

서버의 `.env`에만 다음 값을 설정합니다. `.env`, API 키, 프로젝트 데이터는 커밋하지 않습니다.

```env
API_KEY=...
LLM_BASE_URL=https://gateway.example/v1
LLM_MODEL=approved-model
REPLAN_PAID_CALLS_ENABLED=true
REPLAN_MAX_PAID_RUNS_PER_DAY=20
REPLAN_MAX_AUTO_TRIAGE_PER_DAY=20
REPLAN_LLM_MODE=live
```

언제 호출되는지는 위의 [에이전트 호출 원칙](#에이전트-호출-원칙)을 따릅니다.

### 구성

| 경로 | 역할 |
| --- | --- |
| `apps/web/` | Next.js 작업공간 화면(`stages.ts` 화면 순서, `inbox.tsx` 받은편지함, `risk-panels.tsx` 브리핑·자동 추리·리스크 대장) |
| `services/api/app/` | FastAPI, Excel 처리, 일정 계산기, RAG, 에이전트 런타임, worker |
| `services/api/app/briefing.py`, `risk_register.py` | 등록 시 브리핑, 리스크 대장 |
| `services/api/app/evidence_rag.py` | 근거 문서 색인·검색·인용 연결 |
| `tests/test_evidence_rag.py` | 문서 → RAG → LLM 후보 → 검토 → 승인 E2E 검증 |
| `scripts/` | REPLAY·에이전트 흐름 녹화·재생·평가 스크립트 |
| `data/` | 합성 프로젝트·데모 입력·재생 응답·평가 자료 |
| `docs/` | 제품 흐름, 데모, 연동, 배포, 감사 문서 |

Docker 없이 실행하려면 API(`uvicorn app.main:app --app-dir services/api`), worker(`PYTHONPATH=services/api python -m app.worker`), 웹(`apps/web`에서 `npm run dev`)을 같은 `REPLAN_DATA_DIR`와 `REPLAN_DEMO_TOKEN`으로 실행합니다. API 문서는 `http://localhost:8000/docs`에서 확인할 수 있습니다.

```sh
./.venv/bin/python scripts/agent_flows.py --mode replay
```

현재 회귀 테스트는 일정 계산, 승인·내보내기, REPLAY, 외부 변화 감시, 근거 RAG, 브리핑·자동 추리·리스크 대장, LLM 계약 흐름을 포함합니다. `agent_flows.py`는 녹화된 11개 흐름(브리핑, H04, H02, V08, 외부 공지, 공휴일, X2, X2-대조, X1-A, X1-B, X2 재계산)을 API와 worker로 재생합니다. 실제 유료 모델 평가는 별도 환경에서 실행하며 호출 한도와 비용을 먼저 설정해야 합니다. 과거 평가 수치와 세부 개선 이력은 [에이전트 감사 기록](docs/AGENT_AUDIT.md)에 있습니다.
